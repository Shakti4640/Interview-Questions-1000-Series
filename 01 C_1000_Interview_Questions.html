🧩 Batch 1: C Basics & Syntax (Q1 – Q100)

General Basics

  1. What is the C programming language and who developed it? → A fast, low-level programming language created by Dennis Ritchie.

  2. Explain the difference between compiler and interpreter. → A compiler translates everything at once, an interpreter reads and runs line by line like a slow but careful reader.

  3. What are the major features that distinguish C from assembly language? → C is more human-friendly and less machine-specific, like moving from caveman grunts to actual words.

  4. What does portability mean in the context of C programs? → It means your code can run on many machines without rewriting it—like wearing “one-size-fits-all” clothes.

  5. What is the role of the main() function in a C program? → It’s the program’s official starting point, like the front door everyone must enter through.

  6. Can a C program have more than one main() function? Explain. → No, because the program wouldn’t know which front door to walk through.

  7. What is the return type of main() and why? → Usually int, so it can politely report success or failure to the operating system.

  8. Why do we include stdio.h in most programs? → Because it gives us the tools for input and output, like handing us a keyboard and a megaphone.

  9. What is the significance of the semicolon (;) in C? → It ends statements, just like a period ends a sentence before things get confusing.

  10. Explain what a token is in C. → It’s the smallest meaningful piece of code, like the tiny Lego brick that helps build the whole structure.

Variables and Data Types

  1. What are the basic data types supported by C? → int, float, double, char, and void—the starter pack of data types.

  2. What is the difference between int, short, long, and long long? → They’re all integers but with different storage sizes, like small, medium, large, and extra-large T-shirts.

  3. What is the difference between float and double? → A double holds numbers with more precision, like zooming in with a better camera lens.

  4. What does unsigned mean in variable declaration? → It tells the variable to store only non-negative values, giving it extra room for bigger positives.

  5. Can a variable name start with a number? → No, C won’t allow it—names must start with letters or underscores.

  6. What is the scope of a variable? → It’s the region of the program where the variable can be used, like its personal “operating zone.”

  7. What is the lifetime of a variable? → It’s how long the variable exists in memory, from birth to garbage time.

  8. What are global, local, and static variables? → Global live everywhere, local live only inside their block, static live long but stay private.

  9. What are lvalues and rvalues? → lvalues refer to memory locations, rvalues refer to actual values—like an address vs the letter you receive.

  10. What is the size of an int on a 32-bit vs 64-bit system? → Typically 4 bytes on both, like a classic that rarely changes size.

Operators

  1. What are the different types of operators in C? → Arithmetic, relational, logical, bitwise, assignment, and a few fancy ones like the ternary operator.

  2. Explain the difference between = and ==. → = assigns a value, == checks a value—one gives, the other questions.

  3. What is the modulus operator used for? → It gives the remainder, like checking what’s left after sharing candies evenly.

  4. Explain the difference between prefix and postfix increment operators. → Prefix increases first, postfix increases later—like grabbing a snack before vs after a walk.

  5. What is the order of precedence among arithmetic operators? → Multiplication, division, and modulus come first, then addition and subtraction—like VIPs entering before regular guests.

  6. How does the logical AND (&&) operator differ from bitwise AND (&)? → && works on true/false, & works on bits—one judges logic, the other judges binary fashion.

  7. What is a ternary operator? Give an example. → A mini if-else in one line: x = (a > b) ? a : b;

  8. How does operator associativity affect expression evaluation? → It decides which direction operations happen—left-to-right or right-to-left, like reading styles.

  9. What is the result of integer division in C? → It drops the decimal part, giving you the whole-number chunk only.

  10. What happens if you divide an integer by zero in C? → The program crashes or behaves wildly—like trying to split food by zero people.

Control Flow

  1. What are conditional statements in C? → They let the program make decisions, like tiny traffic lights for your code.

  2. Explain how if, else if, and else work. → They check conditions in order and run the first matching block, like a queue of “if not this, try that.”

  3. What is the difference between switch and if statements? → switch handles many fixed values neatly, while if handles all kinds of conditions.

  4. Can a switch statement work with floating-point numbers? → No, it only plays nicely with integers and characters.

  5. What is the purpose of the break statement? → It stops loops or switch cases immediately, like pulling the emergency brake.

  6. How is the continue statement used in loops? → It skips the current iteration and jumps to the next loop cycle, like saying “next!” quickly.

  7. What is an infinite loop? Give an example. → A loop that never ends, like while(1){}.

  8. What are the three types of loops in C? → for, while, and do-while—the looping trio.

  9. How does a for loop differ from a while loop? → A for loop packs setup, condition, and update in one line; a while keeps them separate.

  10. Can a for loop run indefinitely? How? → Yes, by leaving out the condition: for(;;){}.

Functions

  1. What is a function in C? → A reusable block of code that performs a task, like a mini-machine you can call anytime.

  2. How do you declare and define a function? → Declare by stating its name, return type, and parameters; define by adding the actual code body.

  3. What is the difference between a function declaration and a definition? → A declaration introduces it; a definition does the real work.

  4. What is a function prototype and why is it important? → It tells the compiler what the function looks like before it’s used, preventing confusion.

  5. How does recursion work in C? → A function calls itself until a stopping condition is met, like a mirror reflecting another mirror.

  6. What are inline functions and when are they used? → They ask the compiler to insert code directly to avoid call overhead, good for tiny, speedy tasks.

  7. What is the purpose of the return statement? → It sends back a value and ends the function’s execution.

  8. Can a function return more than one value? → Not directly, but you can use pointers, structs, or arrays to sneak in multiple results.

  9. How do you pass an array to a function? → By passing the array’s name, which acts like a pointer to its first element.

  10. What is call by value vs call by reference? → Call by value sends a copy; call by reference sends the real address like handing over the actual key.

Preprocessor Directives

  1. What is a preprocessor in C? → A tool that prepares your code before compilation, like a chef chopping veggies before cooking.

  2. Explain the purpose of the #include directive. → It pulls in external code or libraries so you don’t reinvent the wheel.

  3. What does #define do? → It creates a macro—basically a shortcut or nickname for something.

  4. How do you write a multi-line macro? → By ending each line with a backslash \ so it continues smoothly.

  5. What is conditional compilation? → It allows code to compile only if certain conditions are met, like selective VIP entry.

  6. What is the difference between #ifdef, #ifndef, and #if? → #ifdef checks if defined, #ifndef checks if not defined, and #if checks a condition.

  7. Can macros take arguments? → Yes, they can act like mini-functions without the rules.

  8. What is the use of #undef? → It removes a macro definition, basically “forget this ever existed.”

  9. How is #pragma used? → It gives special instructions to the compiler, like passing secret notes.

  10. What happens during macro expansion? → The macro gets replaced with its actual content, like unfolding a shortcut into full text.

Pointers (Introduction)

  1. What is a pointer in C? → A variable that stores a memory address instead of a regular value.

  2. How do you declare a pointer variable? → By using *, like int *p;.

  3. What does the * operator mean when used with pointers? → It dereferences the pointer to access the value it points to.

  4. What does the & operator do? → It gives you the memory address of a variable.

  5. What is the value of a null pointer? → It holds zero as an address, meaning it points nowhere.

  6. How do you assign the address of a variable to a pointer? → Use &, like p = &x;.

  7. What is pointer arithmetic? → Doing math on pointers to move through memory step by step.

  8. How do you increment a pointer? → By doing p++, which moves it to the next element type-sized slot.

  9. What is a void pointer and when would you use it? → A pointer with no type, useful for generic data handling.

  10. What are function pointers? → Pointers that store the address of a function so you can call it indirectly.

Arrays and Strings

  1. How do you declare an array in C? → By specifying type and size, like int a[5];.

  2. What is the difference between an array and a pointer? → An array is a fixed block of memory; a pointer just points to a memory location.

  3. How do you initialize an array during declaration? → By listing values in braces, like int a[3] = {1, 2, 3};.

  4. What happens if you access an array out of bounds? → You get unpredictable behavior, like wandering into someone else’s backyard.

  5. How do you find the length of an array? → Using sizeof(a) / sizeof(a[0]) for static arrays.

  6. How are multidimensional arrays represented in memory? → In row-major order, one row after another in a long line.

  7. What is a string in C? → A character array ending with a special zero byte.

  8. How do you declare and initialize a string? → Like char s[] = "Hello";.

  9. What is the difference between a string literal and a character array? → A literal lives in read-only memory; a char array is writable.

  10. How are strings terminated in C? → With a null character '\0', like a tiny end-of-message flag.

String Handling

  1. What does the function strlen() do? → It counts the number of characters in a string before the '\0'.

  2. How does strcpy() differ from strncpy()? → strcpy() copies fully; strncpy() copies only up to a limit.

  3. What is the purpose of strcmp()? → It compares two strings and tells whether one is smaller, equal, or bigger.

  4. What happens if you pass overlapping strings to strcpy()? → You get undefined behavior, like writing while erasing your own notes.

  5. How do you concatenate two strings in C? → Use strcat() or strncat() to glue them together.

  6. How do you safely copy strings to avoid buffer overflow? → Use strncpy() or check lengths manually like a careful guardian.

  7. What is the difference between memcpy() and strcpy()? → memcpy() copies raw bytes; strcpy() copies characters until '\0'.

  8. What is the purpose of the null terminator '\0'? → It marks the end of a string so functions know when to stop.

  9. How does printf("%s", str) know where to stop printing? → It stops when it reaches the '\0' terminator.

  10. What is the difference between single quotes ('a') and double quotes ("a") in C? → Single quotes hold one character; double quotes hold a full string.

Miscellaneous / Edge Cases

  1. Can you have a function inside another function in C? → No, C doesn’t allow nested functions.

  2. What are header files and why are they important? → They contain declarations and help share code across files.

  3. What is the use of the const keyword? → It protects a value from being changed.

  4. What is the difference between const int *p and int * const p? → The first forbids changing the value, the second forbids changing the pointer.

  5. Can you modify a string literal in C? → No, doing so causes undefined behavior.

  6. What is the difference between compile-time and runtime errors? → Compile-time errors happen before running; runtime errors happen while running.

  7. What are implicit and explicit type conversions? → Implicit happens automatically; explicit happens with a cast.

  8. What is the use of the sizeof operator? → It tells you how much memory a type or variable occupies.

  9. What is the purpose of the volatile keyword? → It tells the compiler a value may change unexpectedly.

  10. What does “undefined behavior” mean in C? Give examples. → It means anything can happen; examples include dividing by zero or accessing out-of-bounds memory.

🧠 Batch 2: Memory Management & Pointers (Q101–Q200)

Stack vs Heap Basics

  1. What is the difference between stack memory and heap memory? → Stack is tiny, automatic, and fast; heap is big, manual, and slower.

  2. Where are local variables stored in memory? → They live on the stack like guests who don’t stay long.

  3. What happens when you exceed the stack size? → The program crashes with a dramatic “stack overflow” moment.

  4. How is heap memory allocated in C? → By asking the system nicely using functions like malloc().

  5. What is the role of malloc() in dynamic memory management? → It grabs a chunk of memory for you from the heap.

  6. How is memory allocated differently with calloc() compared to malloc()? → calloc() gives you clean, zero-filled memory while malloc() hands you whatever is lying around.

  7. What is the purpose of realloc()? → It resizes an already allocated memory block when you change your mind.

  8. What happens if you free() the same memory twice? → Your program may behave wildly, like a confused magician repeating the same trick.

  9. How do you check if malloc() failed? → You see if it returned NULL, the universal sign of “no memory left.”

  10. What is a memory leak? → It’s when memory is allocated but never freed, like forgetting to turn off a tap.

Dynamic Memory Operations

  1. How do you release dynamically allocated memory? → You call free() to politely return the memory back to the system.

  2. What happens if you forget to call free()? → The memory just sits there forever like a guest who never leaves.

  3. Can you free memory not allocated by malloc()? → No, doing that is like returning an item you never bought.

  4. What is the difference between static and dynamic allocation? → Static is fixed at compile time, dynamic changes at runtime like a flexible plan.

  5. What is meant by "dangling pointer"? → It’s a pointer pointing to memory that’s gone—like holding an address to a demolished house.

  6. How can dangling pointers be prevented? → Set pointers to NULL after freeing them so they don’t wander off.

  7. What does “heap corruption” mean? → It means your program accidentally messed up heap memory, like scribbling on the wrong notebook.

  8. What is fragmentation in heap memory? → It’s when free memory gets scattered into tiny pieces that don’t fit your needs well.

  9. What are best practices to avoid memory leaks in C? → Always free what you allocate and keep track of every pointer like a responsible babysitter.

  10. How can tools like valgrind help with memory debugging? → They spot memory leaks and errors like a detective with x-ray glasses.

Pointer Fundamentals (Deeper Concepts)

  1. What is pointer arithmetic? → It’s doing math on pointers to move through memory like stepping stones.

  2. How does pointer arithmetic depend on the type of the pointer? → Each step jumps by the size of the pointed-to type, not just one byte.

  3. How do you compute the difference between two pointers? → Subtract them to get how many elements lie between them.

  4. Can you perform arithmetic on void* pointers? → No, because void* doesn’t know what size to step by.

  5. What is a null pointer constant? → It’s a special value that means “points nowhere at all.”

  6. Why is NULL defined as ((void *)0)? → To clearly mark it as a pointer that leads absolutely nowhere.

  7. How do you test if a pointer is valid? → You check if it’s not NULL, though that only weeds out the obviously bad ones.

  8. What does dereferencing a null pointer cause? → An instant crash—like trying to open a door that isn’t there.

  9. Can two pointers point to the same memory? → Yes, they can share the same spot like roommates.

  10. What happens if you increment a pointer beyond an array’s limit? → You wander into forbidden territory, risking wild and unpredictable behavior.

Pointer-to-Pointer and Multi-level Pointers

  1. What is a pointer to a pointer? → It’s a pointer that stores the address of another pointer, like a mailbox for a mailbox.

  2. How do you declare a pointer to a pointer? → You write something like int **p, adding an extra star for extra depth.

  3. What does int **p mean? → It’s a pointer that ultimately leads to an int, just with two hops.

  4. How do you dynamically allocate a 2D array using pointers? → First allocate an array of pointers, then allocate rows for each pointer.

  5. How do you access elements in a dynamically allocated 2D array? → Use arr[i][j] once everything is properly allocated.

  6. What are triple pointers and when are they used? → They’re pointers to double pointers, used when you need to modify a pointer-to-pointer inside a function.

  7. How do you free a dynamically allocated 2D array? → Free each row first, then free the array of pointers.

  8. Can you return a pointer from a function? → Yes, as long as what it points to still exists afterward.

  9. Why can returning the address of a local variable be dangerous? → Because the variable disappears when the function ends, leaving a pointer to nothingness.

  10. How do you return dynamically allocated memory from a function safely? → Allocate it on the heap and return the pointer so it stays alive outside the function.

Array and Pointer Duality

  1. What is the relationship between arrays and pointers in C? → An array is a contiguous block of elements; its name usually decays to a pointer to the first element, so pointers can be used to iterate the array.

  2. How does arr[i] relate to pointer arithmetic? → arr[i] is exactly the same as *(arr + i) — move i elements from the start and dereference.

  3. Is &arr[0] the same as arr? → Yes: both refer to the address of the first element (they evaluate to the same address in most expressions).

  4. Is arr a pointer? Explain carefully. → Not strictly: arr is an array object, not a pointer, but in most expressions it decays to a pointer to its first element.

  5. How do you pass an array to a function using pointers? → Pass a pointer to its first element (e.g. void f(int *a, size_t n) and call f(arr, n)).

  6. How is sizeof(arr) different from sizeof(ptr)? → sizeof(arr) gives the total bytes of the whole array; sizeof(ptr) gives the size of the pointer itself (typically 4 or 8 bytes).

  7. How do you access multidimensional arrays with pointers? → Use row pointers or double dereference, e.g. a[i][j] or *(*(a + i) + j), or int (*p)[N] = a; p[i][j].

  8. What is a pointer to an array? → It’s a pointer whose target is an entire array (e.g. int (*p)[10] points to an int[10]).

  9. What does the declaration int (*p)[10] mean? → p is a pointer to an array of 10 ints.

  10. How does p[i][j] work internally in memory? → It computes the i-th row pointer p + i, then the j-th element in that row: *(*(p + i) + j).

Const, Volatile, and Restrict

  1. What does the const qualifier mean when applied to pointers? → It marks something as unchangeable, either the pointer, the data, or both.

  2. Differentiate between const int *p, int * const p, and const int * const p. → First: data is constant; second: pointer is constant; third: both are constant.

  3. What is the meaning of the volatile keyword? → It tells the compiler the value may change unexpectedly, so don’t optimize it away.

  4. When is volatile typically used? → With hardware registers, shared-memory variables, and interrupt-modified data.

  5. What happens if you remove volatile from a hardware register variable? → The compiler may assume it never changes and produce dangerously wrong code.

  6. What does the restrict keyword do in C99? → It promises that a pointer is the only way to access its pointed-to data.

  7. How does restrict help with compiler optimizations? → It lets the compiler rearrange and speed up code because it knows there’s no aliasing.

  8. Can restrict be used with multiple pointers to the same memory? → No, that breaks the promise and leads to undefined behavior.

  9. Can you cast away const or volatile? What are the dangers? → You can, but using the result to modify forbidden data can cause crashes or undefined behavior.

  10. Why should you avoid modifying data declared as const? → Because the program never guaranteed it was writable, so changing it can go badly wrong.

Dynamic Data Structures

  1. How do you create a linked list using dynamic memory allocation? → You keep using malloc() to create new nodes and link them one after another.

  2. How do you delete nodes from a linked list in C? → You unlink a node, free it, and carefully move to the next so nothing gets lost.

  3. What is a memory pool (custom allocator)? → It’s a pre-allocated chunk of memory you manage yourself like your own mini-heap.

  4. How does a simple memory allocator work internally? → It splits big memory blocks into smaller ones and keeps track of who’s using what.

  5. How can you use malloc() efficiently in large data structures? → By allocating bigger chunks less often instead of calling malloc() for every tiny piece.

  6. What happens if you forget to free a node in a linked list? → That memory stays stuck forever like a book you never returned.

  7. How do you implement a stack using dynamic memory? → Treat each node as a box and push or pop by adding or removing from the top.

  8. How do you detect a memory leak in a data structure? → Use tools or count allocations and frees to see if something didn’t come back.

  9. How do you deep-copy a dynamically allocated structure? → You allocate new memory and copy every nested piece instead of just copying pointers.

  10. What is the difference between shallow and deep copy? → Shallow copy copies pointers only; deep copy makes full, independent duplicates.

Alignment and Padding

  1. What is data alignment in C? → It means placing data at memory addresses that match the CPU’s preferred boundaries.

  2. Why does alignment matter for performance? → Because aligned data lets the CPU grab it faster without extra work.

  3. What is structure padding? → It’s the filler bytes the compiler adds so each field sits nicely aligned.

  4. How does the compiler decide padding bytes in a struct? → It aligns each member based on its type and adds gaps where needed.

  5. How can you minimize padding in a structure? → Arrange members from largest to smallest so fewer gaps appear.

  6. What does the #pragma pack directive do? → It forces the compiler to shrink alignment, reducing or removing padding.

  7. How can misaligned memory access cause performance issues? → The CPU has to do extra fetching gymnastics to read the data.

  8. Can unaligned access cause program crashes? → Yes—some architectures throw a fit and stop the program.

  9. How can you check the alignment of a variable? → Use sizeof, _Alignof, or print its address and see how it lines up.

  10. What are the typical alignment requirements for 32-bit and 64-bit architectures? → Usually 4-byte alignment on 32-bit systems and 8-byte alignment on 64-bit ones.

Memory Safety & Debugging

  1. What is buffer overflow? → It’s when you stuff more data into a buffer than it can hold, spilling into places it shouldn’t.

  2. How can you prevent buffer overflow in C? → Always check sizes and never trust input to behave itself.

  3. What is stack smashing? → It’s a stack overflow that overwrites important data and causes chaos.

  4. How does Address Space Layout Randomization (ASLR) improve safety? → It scrambles memory locations so attackers can’t guess where anything is.

  5. How does gets() lead to memory corruption? → It reads endlessly without limits, like a kid grabbing candy with no bowl.

  6. What safer alternative should be used instead of gets()? → Use fgets() because it actually respects buffer size.

  7. What is the role of memset() in memory initialization? → It fills memory with a specific value so everything starts clean.

  8. How does memmove() differ from memcpy()? → memmove() safely handles overlapping regions; memcpy() doesn’t.

  9. What is the use of calloc() zero-initialization? → It gives you fresh memory already wiped to zero.

  10. What is a segmentation fault and when does it occur? → It’s a crash that happens when you poke memory you’re not allowed to touch.

Advanced Memory Topics

  1. What is memory mapping (mmap) and how is it used in C? → It maps files or anonymous memory directly into your address space for fast access.

  2. What are memory pages? → They’re fixed-size chunks of memory the OS manages like book pages.

  3. What happens when you allocate a large block of memory (e.g., >1GB)? → The OS often hands you virtual space first and commits real memory only when touched.

  4. How can memory fragmentation affect long-running programs? → Free space gets chopped into useless tiny bits, slowing or blocking future allocations.

  5. How do memory allocators like glibc malloc handle large allocations? → They bypass the normal heap and request big chunks directly from the OS with mmap().

  6. What are garbage collectors, and why doesn’t C have one? → They’re automatic cleanup systems, but C leaves memory control to the programmer.

  7. How do tools like valgrind or AddressSanitizer detect memory issues? → They watch every access and shout when you do anything suspicious.

  8. What is “use after free”? → It’s using a pointer to memory that’s already been returned to the system.

  9. How do you guard against use-after-free errors? → Free carefully and set pointers to NULL so they can’t bite back.

  10. How can you write memory-safe C code for embedded systems? → Keep allocations predictable, avoid dynamic tricks, and check every access like a hawk.

⚙️ Batch 3: Advanced C Features (Q201–Q300)

Structures and Unions

  1. What is a structure in C? A user-defined data type that groups different data items under one name.

  2. How do you declare and define a structure? By using the struct keyword followed by its members inside braces.

  3. How can you initialize a structure at declaration? By assigning values in braces in the same order as the members.

  4. How do you access members of a structure using pointers? By using the arrow operator (->).

  5. What is the size of a structure in memory? It is the sum of member sizes plus any padding added by the compiler.

  6. How does padding affect the size of a structure? It increases the structure’s size to maintain proper data alignment.

  7. How can you minimize padding in structures? By ordering members from largest to smallest data type.

  8. What is the typedef keyword used for with structures? It creates an alias name so the structure can be used without struct.

  9. What are anonymous structures and when are they used? Structures without a name, used for quick one-off groupings of data.

  10. How do you copy one structure to another? By using simple assignment (struct1 = struct2).

  11. What are bit-fields in C? Special structure members that allow storing values using a specific number of bits.

  12. How are bit-fields declared inside a struct? By specifying a type, a member name, and a colon followed by the bit width.

  13. What is the maximum width of a bit-field? It cannot exceed the number of bits in the underlying type.

  14. What are the advantages of using bit-fields? They save memory and simplify handling of tightly packed data.

  15. What are the pitfalls of using bit-fields for hardware registers? Their layout and behavior vary by compiler, making them unreliable for hardware mapping.

  16. Can you take the address of a bit-field? No, because bit-fields do not occupy addressable storage.

  17. What happens if you assign a value larger than the bit-field width? It gets truncated to fit the defined number of bits.

  18. How is bit-field ordering determined? By the compiler’s implementation, which chooses how bits are arranged.

  19. What are implementation-defined behaviors in bit-fields? Ordering, alignment, padding, and underlying type usage may vary across compilers.

  20. Can bit-fields be unsigned? Yes, using an unsigned integer type.

  21. What is a union in C? A data type where all members share the same memory space.

  22. How does memory layout differ between structs and unions? A struct allocates space for all members, while a union allocates space only for its largest member.

  23. How do you initialize a union? By specifying the value for its first member or using designated initializers.

  24. What happens when you assign to one member of a union and read from another? You get undefined behavior unless the types share a common representation.

  25. What are some real-world uses of unions? Memory-efficient variant data storage, protocol parsing, and type reinterpretation.

  26. Can a union contain structures? Yes, structures can be members of a union.

  27. Can a structure contain a union? Yes, unions can be included as structure members.

  28. How is the size of a union determined? By the size of its largest member, plus any alignment padding.

  29. What is a tagged union (discriminated union)? A pattern where a value is paired with a tag indicating which variant is active.

  30. How can you emulate a tagged union pattern in C? By combining a union with an enum tag inside a struct.

  31. What are flexible array members? Struct members declared as arrays without a fixed size for variable-length data.

  32. When were flexible array members introduced (which C standard)? They were introduced in C99.

  33. How do you allocate and use a structure with a flexible array member? Allocate enough memory for the struct plus the required extra array bytes.

  34. Why must flexible array members be the last element in a struct? Because their size isn’t fixed and would disrupt memory layout if placed earlier.

  35. How do you calculate total size of a structure with a flexible array? Add sizeof(struct) and the needed length of the flexible array.

  36. Can a flexible array member be used in a union? No, flexible arrays are not allowed inside unions.

  37. What are some use cases of flexible array members? Variable-length buffers, packets, strings, and dynamic data blocks.

  38. What are potential risks of using them incorrectly? Incorrect sizing can cause memory overruns or undefined behavior.

  39. How do you free a structure containing a flexible array safely? Free the single allocated block with free().

  40. How does the compiler handle flexible array layout internally? It reserves space only for the struct header and treats the array as trailing storage.
