Batch 1: Go Basics & Syntax (Q1–Q100):

Variables, Types & Constants

  1. What is the difference between var and := in Go? → var explicitly declares a variable with optional type; := declares and infers type in short form.

  2. How does Go handle variable type inference? → The compiler infers the type from the assigned value when using := or var without a type.

  3. Explain the zero values for Go’s basic types. → Numeric types → 0, bool → false, string → "", pointers/interfaces → nil.

  4. Can you declare multiple variables in one line? Give an example. → Yes: var a, b, c int = 1, 2, 3.

  5. How do you declare a constant in Go? → const pi = 3.14.

  6. Can constants be of custom types? → Yes, you can define a constant of a user-defined type.

  7. What happens if you try to modify a constant? → Compile-time error; constants are immutable.

  8. Difference between typed and untyped constants. → Typed constants have a specific type; untyped are more flexible and can adapt to context.

  9. How do you declare multiple constants in a block? → const (a = 1; b = 2; c = 3).

  10. Explain iota in Go with an example. → iota auto-increments inside const blocks: const (a = iota; b; c) → 0,1,2.

Control Flow: If, Switch, Loops

  1. How does Go’s if statement differ from other languages? → No parentheses around condition; braces are mandatory.

  2. Can if statements include a short statement before the condition? Give an example. → Yes: if x := f(); x > 0 { ... }.

  3. What is the syntax for a for loop in Go? → for i := 0; i < 10; i++ { ... }.

  4. How do you implement a while loop in Go? → Use for with only a condition: for x < 10 { ... }.

  5. How do you write an infinite loop? → for { ... }.

  6. Explain the use of break and continue. → break exits loop, continue skips to next iteration.

  7. How does the switch statement work in Go? → Matches a value against cases; no implicit fallthrough unless specified.

  8. Can a switch statement handle multiple values in one case? → Yes: case 1, 2, 3:.

  9. What is a type switch? Give a practical example. → Switch on dynamic type: switch v := x.(type) { case int: ... }.

  10. How does fallthrough work in Go’s switch? → fallthrough forces execution to the next case.

Functions

  1. How do you declare a function in Go? → func add(a int, b int) int { return a + b }.

  2. Explain named return values. → Return variables are pre-declared in the signature: func f() (x int) { x = 1; return }.

  3. How do you return multiple values from a function? → return val1, val2.

  4. What are variadic functions? Give an example. → Functions accepting variable args: func sum(nums ...int) int.

  5. How do you pass a function as an argument? → func apply(f func(int) int, x int) int { return f(x) }.

  6. Explain first-class functions in Go. → Functions can be assigned to variables, passed, and returned.

  7. How does Go handle function closures? → Inner functions capture variables from outer scope.

  8. What is defer in Go? → Schedules a function to run after surrounding function returns.

  9. Can deferred functions modify named return values? → Yes, they can alter named return variables.

  10. How does defer interact with panics? → Deferred functions still execute even if a panic occurs.

Pointers

  1. What is a pointer in Go? → A variable storing the memory address of another variable.

  2. How do you get the address of a variable? → Using & operator: ptr := &x.

  3. How do you dereference a pointer? → Using * operator: val := *ptr.

  4. Difference between value and pointer receivers in methods. → Value receiver gets a copy; pointer receiver can modify the original.

  5. Can you have a nil pointer? How is it useful? → Yes, indicates absence of value or uninitialized pointer.

  6. Explain pointer arithmetic limitations in Go. → Go doesn’t allow pointer arithmetic directly, unlike C/C++.

  7. What is a pointer to a pointer? → A pointer holding the address of another pointer.

  8. How do slices use pointers internally? → Slice header contains a pointer to the underlying array.

  9. Can you return a pointer from a function? → Yes, Go safely handles pointers to local variables.

  10. Difference between new() and make() regarding pointers. → new() allocates zeroed value, make() initializes slices, maps, channels.

Data Structures: Arrays & Slices

  1. What is the difference between an array and a slice? → Array has fixed size; slice is dynamic and references an array.

  2. How do you declare a fixed-size array? → var arr [5]int.

  3. How do you declare a slice? → s := []int{1,2,3}.

  4. How does appending to a slice work internally? → Allocates a new array if capacity exceeded; copies old elements.

  5. Explain slice capacity and length. → len(slice) → elements count, cap(slice) → max before realloc.

  6. How do you copy slices? → Using copy(dest, src).

  7. How do you create a slice from an array? → arr[1:3].

  8. How do you delete an element from a slice? → slice = append(slice[:i], slice[i+1:]...).

  9. How do you iterate over a slice efficiently? → for i, v := range slice { ... }.

  10. Explain zero-value slices vs nil slices. → Zero-value slice → []T{}; nil slice → nil, both behave similarly for range.

Maps

  1. How do you declare a map in Go? → m := make(map[string]int).

  2. How do you add, retrieve, and delete keys from a map? → m["k"]=1, v:=m["k"], delete(m,"k").

  3. What happens when you access a non-existent key? → Returns zero value of map type.

  4. How do you check if a key exists in a map? → v, ok := m["k"].

  5. Can a map have slices as keys? Why or why not? → No, slices are not comparable; keys must be comparable.

  6. How do you iterate over a map? → for k,v := range m { ... }.

  8. Can you safely read/write to a map concurrently? → No, need sync.Map or locks.

  9. How do you initialize a map with values at declaration? → m := map[string]int{"a":1, "b":2}.

  10. Explain maps with struct keys. → Struct keys must be comparable (no slices, maps inside).

  4. What is an anonymous struct? → Struct without a type name: p := struct{ Name string }{Name:"A"}.

  7. How do you define methods on a struct? → func (p Person) Greet() { ... }.

  8. Difference between pointer and value receivers. → Pointer receiver modifies original, value receiver works on copy.

  9. How do you compare structs? → All fields must be comparable; use ==.

  10. Can structs contain slices, maps, or other structs? → Yes, nesting is allowed.

  10. Can interfaces contain methods with pointer receivers? → Yes, but only types with matching receivers implement them.

Batch 3: Concurrency in Go (Q201–Q300)

Goroutines

  1. What is a goroutine, and how is it different from a thread? → A goroutine is a lightweight concurrent function managed by Go runtime; threads are OS-level constructs, heavier to create.

  2. How do you start a goroutine? → Prefix a function call with go, e.g., go myFunc().

  3. How does Go schedule goroutines on OS threads? → The Go runtime uses an M:N scheduler mapping goroutines onto OS threads.

  4. Can a goroutine be preempted? → Yes, Go runtime can preempt long-running goroutines for fairness.

  5. How do goroutines share memory? → Through shared variables, requiring synchronization, or via channels.

  6. What is the cost of creating a goroutine? → Very low; initial stack ~2KB and grows dynamically.

  7. How do you wait for a goroutine to finish execution? → Use sync.WaitGroup or receive from a signaling channel.

  8. What happens if a goroutine panics? → It terminates the goroutine; deferred functions run, main continues unless panic propagates.

  9. How do you propagate errors from a goroutine? → Send errors through a channel back to the caller.

  10. How does Go handle thousands of concurrent goroutines efficiently? → Lightweight scheduling, small initial stacks, and multiplexing on few OS threads.

Channels Basics

  1. What is a channel in Go? → A typed conduit for sending and receiving values between goroutines.

  2. How do you declare a channel? → ch := make(chan int).

  3. Difference between buffered and unbuffered channels. → Buffered allows N sends without receiver; unbuffered blocks until receiver is ready.

  4. How do you send and receive from a channel? → Send: ch <- val; Receive: val := <-ch.

  5. How does a blocked send/receive work? → Goroutine waits until opposite operation is ready.

  6. Can channels be directional? Explain with an example. → Yes: var ch chan<- int send-only, var ch <-chan int receive-only.

  7. How do you close a channel? → close(ch); only sender should close.

  8. What happens if you send to a closed channel? → Panic occurs.

  9. How do you detect when a channel is closed during receive? → v, ok := <-ch; ok is false if channel closed.

  10. How do you range over a channel safely? → for v := range ch { ... } stops when channel closed.

Select Statement

  1. How does the select statement work in Go? → Waits on multiple channel operations and executes the first ready case.

  2. How do you use select to implement timeouts? → Combine select with time.After(duration) channel.

  3. Can you have a default case in select? → Yes; executes immediately if no other case ready.

  4. Explain using select with multiple channels. → Each case listens on a channel; first ready executes; blocks if none ready.

  5. How do you prevent goroutine leaks with select? → Include cancellation or timeout cases to avoid blocking forever.

  6. How do you implement fan-in with select? → Merge multiple input channels into one output channel.

  7. How do you implement fan-out with select? → Distribute work to multiple worker goroutines via a shared channel.

  8. Can select detect a closed channel? → Yes; receiving from closed channel yields zero value immediately.

  9. How do you combine time.After with select for timeout? → case <-time.After(d): triggers when timeout occurs.

  10. Explain the use of select in a non-blocking channel operation. → Include a default case to avoid blocking if channel not ready.

Synchronization Primitives: sync Package

  1. How do you use sync.Mutex for safe concurrent access? → Lock before accessing shared data: mu.Lock(); ...; mu.Unlock().

  2. Difference between sync.Mutex and sync.RWMutex. → Mutex → exclusive lock; RWMutex → read lock allows concurrent readers.

  3. How do you use sync.WaitGroup to wait for multiple goroutines? → wg.Add(n) before starting goroutines; wg.Done() inside; wg.Wait() blocks until all done.

  4. How do you use sync.Once for one-time initialization? → once.Do(func(){ ... }) ensures function executes once.

  5. What is the purpose of sync/atomic package? → Provides low-level atomic memory operations for safe concurrent access.

  6. How do you perform atomic operations on integers? → atomic.AddInt32(&x, 1), atomic.LoadInt32(&x), etc.

  7. Can you safely share a map between goroutines using Mutex? → Yes; lock around all map accesses.

  8. Difference between Mutex.Lock() and Mutex.RLock(). → Lock → exclusive; RLock → shared read access.

  9. How do you avoid deadlocks with multiple mutexes? → Acquire locks in consistent order; avoid circular dependencies.

  10. Explain race conditions and how to detect them. → Concurrent unsynchronized access to shared data; detect with go run -race.

Concurrency Patterns: Worker Pools

  1. What is a worker pool in Go? → A set of goroutines consuming tasks from a shared channel.

  2. How do you implement a worker pool with goroutines and channels? → Start N goroutines reading from a job channel and sending results to a results channel.

  3. How do you distribute work to multiple workers? → Send jobs into a shared job channel; workers pick up tasks concurrently.

  4. How do you handle errors in a worker pool? → Send errors back through a dedicated error channel.

  5. How do you gracefully stop a worker pool? → Close the job channel and wait for workers to finish.

  6. How do you implement dynamic scaling of workers? → Add or remove goroutines based on workload.

  7. How do you avoid starvation in a worker pool? → Ensure fair scheduling and balanced job distribution.

  8. How do you combine multiple worker pools in a pipeline? → Connect output channel of one pool to input channel of next.

  9. How do you handle channel closure in a worker pool? → Workers detect closed job channel and exit gracefully.

  10. How do you collect results from multiple workers efficiently? → Read from a results channel, optionally using a WaitGroup to know when all done.

Fan-out / Fan-in Patterns

  1. Explain the fan-out/fan-in pattern. → Fan-out: multiple goroutines handle tasks; Fan-in: merge results into single channel.

  2. How do you distribute jobs to multiple goroutines? → Send jobs into a shared channel consumed by multiple goroutines.

  3. How do you combine results from multiple channels? → Use fan-in: merge channels into one output channel, often with a goroutine per input.

  4. How do you prevent goroutine leaks in fan-out/fan-in? → Close channels when done; use context or timeout to cancel blocked goroutines.

  5. How do you implement cancellation in fan-out/fan-in using context? → Pass a context.Context to each goroutine and check ctx.Done().

  6. How do you handle panics in fan-out/fan-in pipelines? → Recover in each goroutine and propagate errors safely.

  7. How do you maintain order of results in fan-in? → Include sequence numbers with tasks and reorder after collection.

  8. Can fan-out/fan-in be used for streaming data? → Yes, channels allow streaming of continuous data.

  9. How do you scale fan-out workers dynamically? → Launch new workers or stop idle workers based on load.

  10. Explain practical use cases for fan-out/fan-in in Go. → Parallel processing, web scraping, batch processing, pipelines.

Deadlocks and Race Conditions

  1. What causes deadlocks in Go programs? → Circular waits on channels or mutexes where no goroutine can proceed.

  2. How do you detect deadlocks at runtime? → Program freezes; go run -race or runtime diagnostics can help.

  3. How do you prevent deadlocks when using multiple mutexes? → Acquire locks in a consistent order; avoid holding multiple locks unnecessarily.

  4. What are common signs of race conditions? → Unexpected values, intermittent bugs, crashes.

  5. How do you use the Go race detector? → go run -race or go test -race.

  6. Can channels alone prevent race conditions? → Yes, if used properly to synchronize access; otherwise, shared memory can race.

  7. How do you handle concurrent writes to a shared map? → Use sync.Mutex or sync.Map.

  8. Explain a scenario where sync.RWMutex prevents data races. → Multiple readers can access map concurrently while writer holds exclusive lock.

  9. How do you avoid race conditions in a worker pool? → Synchronize access to shared resources using channels or mutexes.

  10. Can deferred functions cause deadlocks? → Yes, if they hold locks that block other goroutines indefinitely.

Context Package in Concurrency
