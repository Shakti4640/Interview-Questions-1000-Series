🧩 Batch 1 — Rust Basics & Syntax (Q1–Q100)

🟢 Section 1: Core Syntax & Fundamentals

  1. What is Rust, and what are its primary design goals? → Rust is a systems programming language focused on safety, speed, and concurrency.

  2. How does Rust ensure memory safety without a garbage collector? → Rust uses ownership, borrowing, and lifetimes to manage memory at compile time.

  3. What is the difference between let and let mut in Rust? → let creates an immutable variable, let mut creates a mutable variable.

  4. What is a shadowed variable in Rust? → A shadowed variable is a new variable with the same name that overrides the previous one.

  5. How do you define and use constants in Rust? → Use const NAME: TYPE = VALUE; and refer to it by name.

  6. Explain the difference between const and static. → const is immutable and inlined, static has a fixed memory location and can be mutable with unsafe.

  7. How is type inference handled in Rust? → Rust automatically infers the variable type from the assigned value if not explicitly declared.

  8. How do you explicitly specify the type of a variable? → By writing let variable_name: Type = value;.

  9. What is the difference between scalar and compound data types in Rust? → Scalars hold a single value (like integers), compounds hold multiple values (like tuples and arrays).

  10. What are the four primary scalar types in Rust? → Integer, floating-point, boolean, and character (i32, f64, bool, char).

🟢 Section 2: Data Types & Structures

  1. What is the difference between a tuple and an array? → A tuple can hold multiple types, an array holds elements of the same type.

  2. How do you declare and access a tuple in Rust? → let t = (1, "hello", 3.5); Access with t.0, t.1, etc.

  3. How can you destructure a tuple into individual variables? → let (a, b, c) = t;

  4. How do you create an array of 10 zeros in Rust? → let arr = [0; 10];

  5. How do you initialize a vector with values? → let v = vec![1, 2, 3];

  6. How is Vec<T> different from an array? → Vec<T> is dynamically sized and heap-allocated; arrays are fixed-size and stack-allocated.

  7. What is a slice in Rust, and how does it differ from an array reference? → A slice is a view into a portion of an array or vector, without owning the data.

  8. What is the purpose of the & symbol in Rust? → & creates a reference to a value without taking ownership.

  9. How do you get a slice of an array or vector? → &arr[start..end]

  10. What are the differences between stack and heap memory in Rust? → Stack is fast, fixed-size, and stores local variables; heap is slower, dynamically sized, and stores data needing flexible size.

🟢 Section 3: Control Flow

  1. How does the if statement work in Rust? → It evaluates a condition and executes the block if true, otherwise optionally executes else.

  2. Can if statements be used as expressions in Rust? → Yes, if can return a value assigned to a variable.

  3. What is the syntax for a match expression? → match value { pattern1 => expr1, pattern2 => expr2, _ => default_expr }

  4. How does pattern matching differ from a traditional switch-case statement? → match can destructure, match multiple types, and is exhaustive by requiring all patterns.

  5. What is the _ pattern in match used for? → It acts as a catch-all for any unmatched value.

  6. What is the difference between loop, while, and for loops? → loop repeats indefinitely, while repeats while a condition is true, for iterates over a range or collection.

  7. How do you break out of a loop early? → Use the break statement.

  8. How can you return a value from a loop? → Use break value; to exit and return a value.

  9. How does Rust handle range-based iteration? → Using for i in start..end or start..=end with inclusive ranges.

  10. What does .iter() do on a vector or slice? → It creates an iterator that borrows each element without taking ownership.

🟢 Section 4: Functions

  1. How do you define a function in Rust? → fn function_name(params) -> ReturnType { /* body */ }

  2. What is the difference between an expression and a statement in Rust? → Statements perform actions and don’t return values; expressions evaluate to a value.

  3. Why do Rust functions often omit a return keyword? → The last expression is implicitly returned if not followed by a semicolon.

  4. What is a function signature? → It’s the function’s name, parameters, and return type.

  5. How do you define a function that returns multiple values? → Return a tuple: fn foo() -> (Type1, Type2) { (val1, val2) }

  6. Can you have functions inside functions in Rust? → Yes, nested functions (inner functions) are allowed.

  7. How do you make a function generic over a type T? → fn func<T>(param: T) { /* body */ }

  8. How do you specify the lifetime of a function parameter? → Using lifetime annotations: fn foo<'a>(param: &'a Type) { }

  9. What is a closure in Rust? → A closure is an anonymous function that can capture variables from its environment.

  10. How do closures capture variables from their environment? → By borrowing, mutably borrowing, or taking ownership depending on usage.

🟢 Section 5: Structs & Enums

  1. How do you define a struct in Rust? → struct Name { field1: Type1, field2: Type2 }

  2. What is the difference between a tuple struct and a classic struct? → Tuple structs use unnamed fields like (Type1, Type2); classic structs use named fields.

  3. How do you create an instance of a struct? → let instance = Name { field1: value1, field2: value2 };

  4. What is struct update syntax, and when is it used? → ..other_instance copies remaining fields from another instance when creating a new one.

  5. How can you derive traits like Debug or Clone for a struct? → #[derive(Debug, Clone)] above the struct definition.

  6. How do you define and use an enum? → enum Name { Variant1, Variant2(Type) } and use with Name::Variant1 or Name::Variant2(value).

  7. How do enums in Rust differ from enums in C or Java? → Rust enums can store data per variant and are algebraic data types; C/Java enums are simple constants.

  8. What is a “variant” in an enum? → A named option/value within an enum.

  9. How can enums hold different data types in different variants? → Each variant can have its own associated type or tuple of types.

  10. How do you implement methods for enums using impl blocks? → impl EnumName { fn method(&self) { /* body */ } }

🟢 Section 6: Ownership & Borrowing (Intro level)

  1. What is ownership in Rust? → Ownership is a set of rules that governs how memory is managed through a single owner for each value.

  2. What happens when a variable goes out of scope? → Rust automatically drops (frees) the memory of the variable.

  3. What is a move in Rust, and when does it occur? → A move transfers ownership from one variable to another, usually when assigning or passing a non-Copy type.

  4. What does the Copy trait do? → It allows values to be duplicated implicitly instead of moved.

  5. What is the difference between Copy and Clone? → Copy duplicates automatically, Clone requires an explicit method call.

  6. How do references prevent ownership transfers? → References borrow the value without taking ownership.

  7. What are the rules for mutable and immutable references? → You can have multiple immutable references or one mutable reference at a time, not both simultaneously.

  8. Can you have multiple mutable references at once? → No, only one mutable reference is allowed at a time.

  9. What does a dangling reference mean, and how does Rust prevent it? → A dangling reference points to freed memory; Rust prevents it using ownership and lifetimes.

  10. What is the lifetime of a reference? → The scope during which the reference is valid.

🟢 Section 7: Error Handling

  1. What is the difference between panic! and Result? → panic! stops execution immediately, Result returns recoverable errors.

  2. When should you use panic! versus Result? → Use panic! for unrecoverable errors, Result for recoverable ones.

  3. How do you propagate errors using the ? operator? → Append ? to a Result or Option to return the error automatically if it occurs.

  4. What is the Option type used for? → To represent a value that may or may not be present.

  5. What are Some and None in Rust? → Some(value) holds a value; None represents absence of a value.

  6. How do you handle an Option safely without panicking? → Use pattern matching, if let, or combinators like .unwrap_or() or .map().

  7. What is the difference between unwrap() and expect()? → Both panic on None/Err, but expect() allows a custom error message.

  8. How do you define a custom error type? → Implement struct or enum and optionally implement std::error::Error and Display.

  9. What does the From trait do for error conversions? → Allows automatic conversion from one error type to another.

  10. How do you chain multiple error operations together? → Use combinators like and_then() or the ? operator to propagate errors.

🟢 Section 8: Modules, Packages, & Crates

  1. What is a module in Rust? → A module is a namespace that organizes code into separate scopes.

  2. How do you define a module using mod? → mod module_name { /* items */ }

  3. What is the difference between pub and private items in a module? → pub makes items accessible outside the module; private items are only accessible inside.

  4. How do you refer to an item from another module? → Use module_name::item_name.

  5. What is the purpose of the use keyword? → It brings paths or items into scope for easier access.

  6. How do you prevent naming conflicts using aliases? → Use use module::item as alias;.

  7. What is a crate in Rust? → A crate is a compilation unit or package in Rust.

  8. What is the difference between a binary and a library crate? → Binary crates compile to executables; library crates compile to reusable libraries.

  9. How do you import external crates? → Add them to Cargo.toml and use extern crate crate_name; or use crate_name::item;.

  10. What is the role of Cargo.toml? → It defines the project’s metadata, dependencies, and configuration.

🟢 Section 9: Cargo & Build System

  1. What is Cargo, and what problems does it solve? → Cargo is Rust’s package manager and build tool that handles dependencies, compilation, and project management.

  2. How do you create a new Cargo project? → cargo new project_name

  3. How do you build and run a Rust program with Cargo? → cargo build to compile, cargo run to compile and execute.

  4. What does the cargo check command do? → Checks code for errors without producing a binary.

  5. How do you add dependencies to a project? → Add them under [dependencies] in Cargo.toml.

  6. How do you specify dependency versions in Cargo.toml? → Use crate_name = "version" or version ranges like "^1.2.3".

  7. How do you build a release version of your program? → cargo build --release

  8. What does the target directory contain? → Compiled binaries, intermediate files, and build artifacts.

  9. How do you run unit tests using Cargo? → cargo test

  10. How do you publish a crate to crates.io? → cargo publish after logging in and ensuring Cargo.toml metadata is correct.

🟢 Section 10: Miscellaneous Fundamentals

  1. What are macros in Rust? → Macros are metaprogramming tools that generate code at compile time.

  2. How do declarative macros (macro_rules!) work? → They match patterns and expand them into code according to defined rules.

  3. What’s the difference between a macro and a function? → Macros operate on code itself and can take variable arguments; functions operate on values at runtime.

  4. How can you print formatted output using macros? → Use println!, format!, or eprint! macros.

  5. What is the purpose of the derive attribute? → Automatically implements common traits like Debug, Clone, or PartialEq.

  6. What is the dbg!() macro used for? → It prints a value and its source location for debugging purposes.

  7. What are raw strings, and when would you use them? → Strings like r#"text"# that ignore escape sequences, useful for regex or file paths.

  8. How do you use Unicode in Rust string literals? → Include Unicode with escape sequences like \u{1F600} or directly in UTF-8.

  9. What is the difference between String and &str? → String is heap-allocated and mutable; &str is a borrowed string slice, usually immutable.

  10. How do you convert between String and &str safely? → Use &string to get &str and string.to_string() or String::from(&str) to get String.

🧠 Batch 2 — Ownership & Borrowing (Q101–Q200)

🟩 Section 1: Ownership Core Principles

  1. What are the three core rules of ownership in Rust? → Each value has a single owner, ownership can be transferred (move), and memory is freed when the owner goes out of scope.

  2. Why does Rust have ownership instead of garbage collection? → To ensure memory safety without runtime overhead.

  3. What happens to memory when an owner variable goes out of scope? → The memory is automatically deallocated.

  4. What is meant by a move in Rust? → Ownership of a value is transferred from one variable to another.

  5. When does a move operation occur automatically? → When assigning a non-Copy type to another variable or passing it to a function.

  6. What happens if you try to use a moved value? → Compiler error: value has been moved and is no longer valid.

  7. Which types implement the Copy trait by default? → Primitive scalar types like integers, floats, and bool.

  8. How does the Copy trait affect ownership semantics? → Values are duplicated rather than moved, so the original remains valid.

  9. How can you manually implement the Clone trait for a struct? → Define a clone(&self) -> Self method that returns a copy of the struct.

  10. What is deep vs shallow cloning? → Deep clones copy all nested data; shallow clones copy only the outer structure.

🟩 Section 2: Borrowing Basics

  1. What does borrowing mean in Rust? → Temporarily allowing another variable to access a value without taking ownership.

  2. How do you borrow a value immutably? → Use &value.

  3. How do you borrow a value mutably? → Use &mut value.

  4. Why can you only have one mutable reference at a time? → To prevent data races and ensure memory safety.

  5. Can you mix mutable and immutable borrows in the same scope? → No, they cannot coexist simultaneously.

  6. What happens if you attempt to use a reference after the value it refers to has been dropped? → Compiler error: use of a dangling reference is prevented.

  7. Why is borrowing essential for function parameters? → It allows functions to access data without taking ownership.

  8. What does the borrow checker verify during compilation? → That references obey ownership, mutability, and lifetime rules.

  9. How does Rust ensure aliasing and mutability safety? → By enforcing rules: either many immutable or one mutable reference.

  10. What is the lifetime of a reference during a borrow? → The reference lasts as long as the owner or scope allows.

🟩 Section 3: Move Semantics & Copy Trait

  1. How does Rust decide whether to move or copy a variable? → Depends on whether the type implements Copy; Copy types are copied, others are moved.

  2. Why does String move while i32 copies? → String manages heap memory, i32 is a simple stack value.

  3. What does the Copy trait require from a type’s fields? → All fields must also implement Copy.

  4. Why can’t types that manage heap memory (like Vec) implement Copy? → Copying them would duplicate ownership of heap memory, causing double-free errors.

  5. How do you explicitly copy a non-Copy type? → Use .clone().

  6. What’s the difference between clone() and to_owned()? → clone() duplicates data; to_owned() converts borrowed data into owned data.

  7. How does Rc<T> help with multiple ownership? → Enables multiple references to the same value with reference counting.

  8. Why can Rc<T> not be used in multithreaded programs safely? → It is not Send or Sync and is not thread-safe.

  9. What is Arc<T>, and how does it differ from Rc<T>? → Arc<T> is atomic and thread-safe, unlike Rc<T>.

  10. When should you use Rc vs Arc? → Rc for single-threaded, Arc for multi-threaded scenarios.

🟩 Section 4: Smart Pointers

  1. What is a smart pointer in Rust? → A data structure that behaves like a pointer and manages ownership.

  2. How is Box<T> different from a normal reference? → Box<T> owns the value on the heap, whereas a reference does not.

  3. When would you use Box<T>? → To allocate data on the heap or for recursive types.

  4. How does Box<T> affect ownership and lifetimes? → Boxed values follow Rust’s ownership rules; memory is freed when Box is dropped.

  5. What happens when a Box<T> goes out of scope? → The heap-allocated memory is deallocated.

  6. What is an Rc<T> and how does reference counting work? → Rc<T> tracks the number of owners and frees memory when the count reaches zero.

  7. How do you increase or decrease the reference count of an Rc<T>? → Cloning increases it; dropping decreases it.

  8. What happens if you clone an Rc<T>? → Reference count is incremented.

  9. How do you check the strong reference count of an Rc<T>? → Use Rc::strong_count(&rc_value).

  10. What is a weak reference (Weak<T>) and why is it useful? → A reference that doesn’t increase the strong count, avoiding reference cycles.

🟩 Section 5: RefCell, Interior Mutability

  1. What is the concept of interior mutability in Rust? → Mutating data through an immutable reference using special types like RefCell.

  2. What problem does RefCell<T> solve? → Enables mutable access at runtime while enforcing borrow rules.

  3. How does RefCell enforce borrowing rules at runtime? → Tracks borrow counts dynamically, panicking on violations.

  4. What is the difference between borrow() and borrow_mut() in RefCell? → borrow() for immutable, borrow_mut() for mutable access.

  5. What happens if you try to mutably borrow twice from a RefCell? → Runtime panic.

  6. What error type does RefCell return on invalid borrowing? → BorrowError or BorrowMutError.

  7. When should you use RefCell instead of Mutex? → For single-threaded interior mutability.

  8. Can RefCell be shared across threads safely? → No, it is not thread-safe.

  9. How can you combine Rc<RefCell<T>> to enable shared, mutable state? → Rc for shared ownership, RefCell for interior mutability.

  10. Why is Rc<RefCell<T>> often used in GUI or graph-like structures? → Allows multiple nodes to share and mutate data safely in single-threaded context.

🟩 Section 6: Lifetimes — The Basics

  1. What is a lifetime in Rust? → A scope for which a reference is valid.

  2. Why does Rust need lifetimes at all? → To prevent dangling references.

  3. How does the compiler infer lifetimes automatically? → By analyzing reference usage and following lifetime elision rules.

  4. When do you need to explicitly annotate lifetimes? → When the compiler cannot infer them unambiguously.

  5. What does 'static lifetime mean? → Data lives for the entire duration of the program.

  6. What is a dangling reference and how does Rust’s lifetime system prevent it? → A reference pointing to freed memory; Rust enforces lifetimes to avoid it.

  7. Can two references with different lifetimes point to the same data? → Yes, as long as their usage follows borrowing rules.

  8. How are lifetimes related to scope? → Lifetimes cannot exceed the scope of the owner.

  9. What happens if you return a reference to a local variable? → Compiler error: reference would be dangling.

  10. How do lifetimes improve safety without affecting performance? → They enforce compile-time guarantees without runtime checks.

🟩 Section 7: Lifetime Annotations

  1. What does the syntax 'a mean in a function signature? → It’s a named lifetime parameter.

  2. How do you define a function with two references sharing the same lifetime? → Use the same lifetime annotation, e.g., <'a>(x: &'a i32, y: &'a i32).

  3. What is lifetime elision? → Compiler infers lifetimes when not explicitly written.

  4. What are the three lifetime elision rules? → Each input has a lifetime, &self/&mut self gets implicit lifetime, single output lifetime = input lifetime.

  5. When do you need to write lifetimes explicitly despite elision rules? → When multiple inputs and outputs prevent the compiler from inferring lifetimes.

  6. How do you annotate struct fields that hold references? → Use lifetime parameters, e.g., struct Foo<'a> { r: &'a i32 }.

  7. What happens if you forget to annotate a lifetime in a struct containing a reference? → Compiler error: missing lifetime specifier.

  8. Can enums have lifetime parameters too? → Yes, if they hold references.

  9. How do lifetime parameters affect methods on a struct? → Methods may need lifetime annotations to match struct fields.

  10. What is the difference between 'static data and static lifetimes? → 'static refers to data that lives for the entire program; static is a global variable.

🟩 Section 8: Lifetime Examples & Applications

  1. How do you return the longer of two string slices safely? → Annotate the function with a lifetime tied to the input slices.

  2. How do you tie lifetimes of parameters to the return type in a function? → Use the same lifetime annotation for inputs and output.

  3. Can you have multiple lifetimes in one function signature? → Yes, for independent references.

  4. How do lifetimes interact with generic type parameters? → You can bound generics with lifetimes, e.g., T: 'a.

  5. What is a “lifetime bound” in generics? → Constrains a generic type to not outlive a particular lifetime.

  6. What does T: 'a mean in a generic constraint? → Type T must live at least as long as lifetime 'a.

  7. How do lifetimes affect trait implementations? → Trait methods may need lifetime annotations to ensure safety.

  8. How do you specify a trait object with a particular lifetime? → Use syntax like &'a dyn Trait.

  9. Can lifetime parameters appear in trait definitions? → Yes, for references inside traits.

  10. What is a higher-ranked trait bound (HRTB)? → Allows a trait to be valid for all possible lifetimes.

🟩 Section 9: Concurrency & Borrowing Rules

  1. Why can’t Rust have data races under its ownership model? → Ownership rules enforce single mutable access and safe sharing.

  2. What happens when two threads attempt to access the same data mutably? → Compiler prevents it unless wrapped in Mutex or similar.

  3. How does Send trait ensure thread-safe data transfer? → Types implementing Send can be safely moved to another thread.

  4. What is the Sync trait, and how does it differ from Send? → Sync allows safe shared references across threads; Send allows ownership transfer.

  5. How can you make a type Send or Sync manually? → Implement the traits, usually via unsafe, with guarantees of thread safety.

  6. What does Arc<Mutex<T>> achieve? → Thread-safe shared ownership with interior mutability.

  7. How do lifetimes ensure safe concurrency in async code? → They prevent references from outliving the data across await points.

  8. Can async functions hold references across await points safely? → Only if lifetimes allow; often requires 'static references.

  9. What are 'static lifetimes commonly used for in async tasks? → For data that lives for the entire program or is thread-safe.

  10. Why does tokio::spawn often require 'static lifetimes? → Tasks may outlive the current stack frame; 'static ensures safety.

🟩 Section 10: Advanced Ownership Scenarios

  1. How do you safely transfer ownership of a large data structure between threads? → Wrap it in Box or Arc and move it into the thread.

  2. What does std::mem::take() do? → Replaces a value with its default, returning the original.

  3. How does std::mem::replace() differ from take()? → replace() swaps with a provided value; take() swaps with Default::default().

  4. What is std::mem::swap() and when is it used? → Exchanges two values without cloning; used for in-place swaps.

  5. How can you temporarily move out of a struct field? → Use Option::take() or mem::replace().

  6. What does the Option::take() method do and why is it useful for ownership transfers? → Sets the option to None and returns the original value.

  7. How do you design APIs that avoid unnecessary cloning? → Accept references or use smart pointers like Rc/Arc.

  8. What are common ownership pitfalls when using iterators? → Moving items unexpectedly or holding references beyond scope.

  9. How can interior mutability patterns violate the spirit of Rust’s borrowing rules if misused? → They can allow multiple mutable accesses at runtime, causing panics.

  10. What strategies can developers use to debug borrow checker errors effectively? → Read error messages carefully, simplify lifetimes, and break complex expressions into smaller steps.

⚙️ Batch 3 — Advanced Rust Features (Q201–Q300)

🧩 Section 1: Traits — Definition & Implementation

  1. What is a trait in Rust? → A collection of methods that define shared behavior for types.

  2. How do you define a new trait? → Use trait TraitName { fn method(&self); }.

  3. How do you implement a trait for a struct? → impl TraitName for StructName { fn method(&self) { ... } }.

  4. Can you implement multiple traits for a single type? → Yes, a type can implement as many traits as needed.

  5. What is a trait bound? → A constraint specifying that a type must implement a certain trait.

  6. How do you specify a trait bound in a function signature? → Use syntax like fn func<T: TraitName>(x: T) { ... }.

  7. What is the difference between impl Trait and generic parameters with trait bounds? → impl Trait is shorthand for a single type implementing the trait; generics with bounds are explicit and reusable.

  8. How do you define a default method inside a trait? → Provide a method body in the trait definition: fn method(&self) { ... }.

  9. Can a default method call another method within the same trait? → Yes, it can call other trait methods.

  10. How do you override a default method implementation? → Implement the method explicitly in the impl block for the type.

🧩 Section 2: Traits — Advanced Concepts

  1. What is the orphan rule in Rust? → You can implement a trait for a type only if either the trait or the type is local.

  2. Why can’t you implement external traits for external types directly? → To avoid conflicts with other crates implementing the same trait.

  3. How do you use the newtype pattern to bypass the orphan rule safely? → Wrap the external type in a local struct and implement the trait for that.

  4. What is a marker trait? → A trait with no methods, used to signal a property or capability of a type.

  5. Give examples of marker traits in the standard library. → Send, Sync, Copy.

  6. What is the Sized trait, and when is it automatically implemented? → Indicates types with a known size at compile time; automatically implemented for most types.

  7. How can you define a function that works on both sized and unsized types? → Use T: ?Sized to allow unsized types.

  8. What does the ?Sized bound mean? → The type may or may not have a known compile-time size.

  9. What is a trait object (dyn Trait)? → A pointer to a value with dynamic dispatch, allowing runtime polymorphism.

  10. What are the trade-offs between static and dynamic dispatch? → Static dispatch is faster and monomorphized; dynamic dispatch is flexible but slightly slower.

🧩 Section 3: Generics — Basics

  1. What are generics in Rust? → Types or functions that operate on multiple types without duplicating code.

  2. Why are generics important for performance and code reuse? → They allow zero-cost abstraction through monomorphization.

  3. How do you define a generic function? → fn func<T>(arg: T) { ... }.

  4. How do you define a generic struct? → struct StructName<T> { field: T }.

  5. How do you define a generic enum? → enum EnumName<T> { Variant(T) }.

  6. What is monomorphization in Rust? → Compiler generates concrete versions of generic functions for each type used.

  7. How does monomorphization impact compile times and binary size? → Increases compile time and binary size due to duplication for each type.

  8. Can generics be nested? → Yes, types can have generic parameters that are themselves generic.

  9. How do you combine multiple trait bounds for a single generic parameter? → Use T: Trait1 + Trait2.

  10. What is a where clause used for? → To specify complex trait bounds more clearly: fn func<T>() where T: Trait1 + Trait2 { ... }.

🧩 Section 4: Generics — Advanced Topics

  1. What happens when you implement a generic trait for a specific type? → You provide behavior only for that type while keeping the trait generic.

  2. How do you restrict a generic function to numeric types only? → Use trait bounds like T: Add + Sub + Copy.

  3. What is the purpose of PartialEq and PartialOrd traits? → To enable equality and ordering comparisons.

  4. How can you make your custom types comparable? → Implement PartialEq, Eq, PartialOrd, or Ord.

  5. What does Eq add on top of PartialEq? → Guarantees full equivalence (reflexive, symmetric, transitive).

  6. How do you derive traits like Eq and Ord automatically? → Use #[derive(Eq, Ord)] above the type.

  7. What are blanket implementations? → Implementing a trait for all types that satisfy certain bounds.

  8. Can you provide your own blanket implementation safely? → Yes, as long as it doesn’t conflict with existing implementations.

  9. What does T: Default mean in generic code? → T must have a default value (Default::default()).

  10. How do you use trait objects with generics? → Use Box<dyn Trait> or &dyn Trait as generic type parameters.

🧩 Section 5: Closures — Basics
