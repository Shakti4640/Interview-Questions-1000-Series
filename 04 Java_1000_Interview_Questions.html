🧩 Batch 1 — Core Java Basics to Intermediate (Q1–Q100)

Java Basics

  1. What is Java, and why is it platform-independent? → Java runs on the JVM, which makes the same bytecode work on any machine—like magic slippers for code.

  2. Explain the difference between JDK, JRE, and JVM. → JDK is the full toolbox, JRE is the running environment, and JVM is the engine that actually runs your bytecode.

  3. What are the main features of Java? → It’s object-oriented, portable, secure, and has garbage collection to clean up your mess.

  4. What is the difference between Java and other programming languages like C++? → Java removes tricky stuff like pointers and manual memory management, making life a little less stressful.

  5. What is bytecode in Java? → It’s the intermediate code the JVM understands—a universal language for all Java programs.

  6. What is the Java Virtual Machine (JVM)? → It’s the software engine that runs Java bytecode and keeps things platform-independent.

  7. What are the different types of memory areas allocated by JVM? → Heap, Stack, Method Area, PC Registers, and Native Method Stack—like rooms in a tiny code hotel.

  8. What is the role of the Just-In-Time (JIT) compiler in Java? → It turns hot bytecode into machine code on the fly to make your program zoom faster.

  9. What is the difference between a compiler and an interpreter? → A compiler translates everything at once; an interpreter reads it line by line like a storyteller.

  10. What is the significance of the main() method in Java? → It’s the official entry door where every Java program begins its journey.

  11. Why is Java considered an object-oriented language? → Because it focuses on objects and classes, making everything feel modular and neat.

  12. What are objects and classes in Java? → Classes are blueprints, and objects are the actual things built from those blueprints.

  13. What is the difference between a class and an object? → A class is the idea; an object is the real thing created from that idea.

  14. What is a constructor in Java? → It’s a special method that sets up an object when it’s born.

  15. What is the default constructor? → It’s the empty constructor Java auto-creates when you don’t provide one.

  16. Can a constructor be private? → Yes, usually for patterns like singletons to keep object creation controlled.

  17. Can a constructor return a value? → No—constructors don’t return anything, not even a sneaky void.

  18. What is the difference between this and super keywords? → this points to the current class, while super reaches up to the parent class.

  19. What is method overloading? → Same method name, different parameters—a friendly multitasker.

  20. What is method overriding? → When a subclass rewrites a parent method to give it a fresh personality.

Data Types & Variables

  1. What are primitive data types in Java? → They are the basic built-in types like int, char, double, and boolean—Java’s tiny building blocks.

  2. What is the difference between primitive and reference data types? → Primitives store actual values, while references store addresses pointing to objects.

  3. What is type casting in Java? → It’s converting one data type into another—like fitting data into a new costume.

  4. What is the difference between implicit and explicit casting? → Implicit is automatic widening, explicit is manual narrowing.

  5. What are wrapper classes in Java? → Object versions of primitive types, like Integer for int and Double for double.

  6. Why are wrapper classes needed? → They let primitives work in object-only places like collections.

  7. What is autoboxing and unboxing? → Autoboxing converts primitives to wrappers; unboxing converts them back.

  8. What is the default value of different data types in Java? → Primitives get zeros or false, references get null.

  9. What is the difference between == and .equals()? → == checks memory addresses, .equals() checks actual content.

  10. What is the difference between String, StringBuilder, and StringBuffer? → String is immutable, StringBuilder is mutable and fast, StringBuffer is mutable and thread-safe.

Control Flow Statements

  1. What are the different control statements in Java? → Selection (if, switch), looping (for, while, do-while), and jump statements (break, continue, return).

  2. How does the switch statement work? → It checks a value against multiple cases and runs the matching block.

  3. Can a switch statement use a String? → Yes, from Java 7 onward.

  4. What is the difference between break and continue? → Break stops the loop entirely, continue skips to the next iteration.

  5. What is the difference between while and do-while loops? → While checks first, do-while runs once before checking.

  6. Can a for loop be infinite? → Yes—just leave out the condition.

  7. What is the enhanced for loop (for-each loop)? → A simplified loop used to traverse arrays and collections.

  8. What is the difference between return, break, and continue? → Return exits the method, break exits a loop or switch, continue skips to the next loop cycle.

  9. Can we use multiple return statements in a method? → Yes, as long as the flow logically allows it.

  10. What happens if you forget a break in a switch case? → Execution “falls through” into the next case.

OOPs Concepts

  1. What are the four pillars of Object-Oriented Programming? → Inheritance, Polymorphism, Encapsulation, and Abstraction—the fantastic four of OOP.

  2. What is inheritance? → A way for one class to reuse and extend another class’s features.

  3. What is polymorphism? → One action behaving differently depending on the object using it.

  4. What is encapsulation? → Wrapping data and methods together and guarding them with access control.

  5. What is abstraction? → Showing only the important stuff and hiding all the messy details.

  6. What is the difference between abstraction and encapsulation? → Abstraction hides complexity, encapsulation protects access.

  7. What is an abstract class? → A class you can’t fully use until a subclass fills in the missing pieces.

  8. What is an interface? → A contract listing methods that classes must implement.

  9. Can an interface have method implementations? → Yes—default and static methods can have bodies.

  10. What is the difference between an abstract class and an interface? → Abstract classes have partial implementation; interfaces mostly define rules.

  11. Can we create an object of an abstract class? → Nope—it's like trying to use a sketch as a finished machine.

  12. Can a class implement multiple interfaces? → Yes—Java happily allows it.

  13. What is multiple inheritance? → A class having more than one parent.

  14. Does Java support multiple inheritance? → Not with classes, to avoid chaos.

  15. How can we achieve multiple inheritance in Java? → By implementing multiple interfaces.

  16. What is a static method? → A method that belongs to the class, not the object.

  17. Can we override a static method? → No—static methods can only be hidden, not overridden.

  18. What is a final variable, method, or class? → Final variable can’t change, final method can’t be overridden, final class can’t be extended.

  19. What is the difference between final, finally, and finalize()? → final restricts, finally always runs, finalize() was for cleanup but is now basically retired.

  20. What is the super keyword used for? → To call parent class methods, constructors, or access its hidden members.

Exception Handling

  1. What is exception handling in Java? → A way to manage runtime problems without crashing the program.

  2. What are checked and unchecked exceptions? → Checked must be handled at compile time; unchecked appear at runtime.

  3. What is the try-catch block used for? → To wrap risky code and handle errors safely.

  4. Can we have multiple catch blocks? → Yes—each can handle a different exception type.

  5. What is the finally block? → A block that runs no matter what, usually for cleanup.

  6. Can finally block be skipped? → Only if the JVM shuts down unexpectedly.

  7. What is the throw keyword used for? → To manually create and send out an exception.

  8. What is the throws keyword used for? → To declare that a method might toss certain exceptions.

  9. Can we have a try block without catch? → Yes, if you use a finally block.

  10. What is the difference between throw and throws? → throw launches an exception; throws announces potential exceptions.

  11. What happens when an exception is not handled? → The program terminates and the JVM shows an error message.

  12. Can we create custom exceptions in Java? → Yes—Java lets you craft your own exception types.

  13. How do we create a custom exception? → Make a class that extends Exception or RuntimeException.

  14. What is the root class of all exceptions in Java? → Throwable sits at the very top.

  15. What is the difference between Error and Exception? → Errors are severe system issues; exceptions are recoverable program issues.

Collections Framework (Intro)

  1. What is the Java Collections Framework? → A set of ready-made data structures and algorithms to manage groups of objects.

  2. What is the difference between a Collection and a Map? → Collection stores elements; Map stores key-value pairs.

  3. What are the main interfaces in the Java Collections Framework? → List, Set, Queue, Deque, and Map.

  4. What is the difference between List, Set, and Map? → List allows duplicates, Set avoids duplicates, Map stores key-value pairs.

  5. What is the difference between ArrayList and LinkedList? → ArrayList is fast at access, LinkedList is fast at insert/delete.

  6. What is the difference between HashSet and TreeSet? → HashSet is fast and unordered; TreeSet is sorted and slower.

  7. What is the difference between HashMap and TreeMap? → HashMap is fast and unordered; TreeMap is sorted by keys.

  8. What is the difference between Iterator and ListIterator? → Iterator moves forward; ListIterator moves both ways and supports more operations.

  9. What is the difference between fail-fast and fail-safe iterators? → Fail-fast crash on modification; fail-safe work on a copy.

  10. What is the difference between HashMap and Hashtable? → HashMap is non-synchronized and faster; Hashtable is synchronized and older.

  11. What is the load factor in HashMap? → A threshold that triggers resizing, usually 0.75.

  12. What happens if two keys in a HashMap have the same hashcode? → They land in the same bucket and form a chain or tree.

  13. What is the internal structure of a HashMap? → An array of buckets using linked lists or balanced trees.

  14. What is the difference between Array and ArrayList? → Array is fixed-size; ArrayList grows dynamically.

  15. Can we store null values in a HashMap? → Yes—one null key and multiple null values.

Multithreading (Intro)

  1. What is a thread in Java? → A lightweight unit of execution that runs tasks concurrently.

  2. How do you create a thread in Java? → Either extend Thread or implement Runnable and pass it to a Thread object.

  3. What is the difference between extending Thread and implementing Runnable? → Extending limits inheritance; implementing is flexible and preferred.

  4. What is thread synchronization? → A way to prevent multiple threads from messing with shared data at the same time.

  5. What is a synchronized block? → A protected section of code that only one thread can enter at once.

  6. What is a deadlock? → When threads wait on each other forever like stubborn statues.

  7. What is the difference between wait() and sleep()? → wait() releases the lock; sleep() doesn’t.

  8. What is the difference between notify() and notifyAll()? → notify() wakes one waiting thread; notifyAll() wakes them all.

  9. What is thread priority? → A hint to the scheduler about how important a thread is.

  10. What is the difference between a process and a thread? → A process is a full program; threads are smaller tasks inside it sharing resources.

🧠 Batch 2 — Advanced Core Java & JVM Internals (Q101–Q200)

JVM & Memory Management

  1. What are the different components of JVM architecture? → ClassLoader, Runtime Data Areas, Execution Engine, and Native Interface—basically JVM’s internal city map.

  2. What is the ClassLoader in Java? → A module that loads classes into memory like a librarian fetching books.

  3. What are the types of ClassLoaders? → Bootstrap, Extension, and Application ClassLoaders.

  4. What is the purpose of the Bootstrap ClassLoader? → To load core Java classes—it's the boss loader.

  5. What is the Method Area in JVM memory? → A zone storing class-level data like methods, constants, and bytecode.

  6. What is the difference between heap and stack memory? → Heap stores objects; stack stores method calls and local variables.

  7. What is garbage collection in Java? → Automatic cleanup of unused objects—Java’s own housekeeping robot.

  8. How does the garbage collector know which objects to delete? → It checks reachability—if nobody points to it, it’s out.

  9. What are strong, weak, soft, and phantom references? → Different "strengths" of how tightly objects are held for GC decisions.

  10. What are memory leaks in Java, and how do they occur? → When unused objects stay referenced, hogging memory like unreturned library books.

  11. How do you trigger garbage collection manually? → Call System.gc(), but it’s just a polite request, not a command.

  12. What is the finalize() method used for? → A last-chance cleanup callback before GC—like a farewell whisper.

  13. Is it a good idea to rely on finalize()? Why or why not? → No, it’s unpredictable and deprecated.

  14. What is the difference between minor GC and major GC? → Minor GC cleans young generation; major GC cleans old generation and is heavier.

  15. What is the Metaspace in Java 8 and above? → A native-memory area storing class metadata, replacing PermGen.

  16. How do you analyze memory usage in a Java application? → Use profiling tools, logs, and heap dumps.

  17. What tools can be used for profiling Java memory? → VisualVM, JProfiler, YourKit, and Java Mission Control.

  18. What are OutOfMemoryError and StackOverflowError? → OOM means memory ran out; StackOverflow means recursion went wild.

  19. How can you prevent memory leaks in Java? → Remove unwanted references, close resources, and avoid static hoarding.

  20. What is the difference between JVM tuning and profiling? → Tuning adjusts performance settings; profiling inspects behavior to find issues.

Advanced OOP & Design

  1. What is composition in Java? → Using one class inside another to build complex objects.

  2. How does composition differ from inheritance? → Composition uses “has-a”; inheritance uses “is-a”.

  3. What are access modifiers in Java? → Keywords controlling visibility: public, private, protected, and default.

  4. What is the default access modifier? → Package-private—visible only within the same package.

  5. What are nested classes in Java? → Classes defined inside another class.

  6. What are static nested classes? → Nested classes that don’t need an outer class object to be used.

  7. What is an anonymous inner class? → A nameless class created for quick one-time use.

  8. What are local inner classes? → Classes defined inside a method.

  9. What is the purpose of this and super in constructor chaining? → this calls another constructor in the same class; super calls a parent constructor.

  10. What is a copy constructor? → A constructor that makes a new object by copying another one.

  11. How can you implement a copy constructor in Java? → Create a constructor that accepts the same class type and copies its fields.

  12. What is the clone() method in Java? → A method to duplicate objects using the Cloneable mechanism.

  13. What is shallow copy vs deep copy? → Shallow copies references; deep copy clones everything inside too.

  14. How can you achieve deep copy in Java? → Clone fields manually, use copy constructors, or use serialization.

  15. Why should we override the equals() and hashCode() methods together? → To keep consistent behavior in hashed collections.

  16. What is the toString() method used for? → To return a readable string version of an object.

  17. Can we override equals() without overriding hashCode()? → Yes, but it breaks hashed collections.

  18. What is immutability in Java? → When an object cannot be changed after creation.

  19. How do you create an immutable class? → Make fields final, private, no setters, and return copies of mutable fields.

  20. What is the Object class in Java, and what are its key methods? → The root class of all Java classes containing methods like equals, hashCode, toString, clone, and finalize.

Generics

  1. What are generics in Java? → A way to write flexible, type-safe classes and methods.

  2. Why were generics introduced? → To prevent type errors and reduce casting headaches.

  3. What are the advantages of using generics? → Type safety, cleaner code, and reusable components.

  4. What is type erasure in Java generics? → The process where generic types vanish at runtime.

  5. Can generics be used with primitive types? → No—only reference types.

  6. What are bounded type parameters? → Type parameters restricted using extends or super.

  7. What is the difference between <T>, <T extends Class>, and <T super Class>? → <T> is generic, extends is upper-bound, super is lower-bound.

  8. What are wildcards in generics? → Question marks that allow flexible unknown types.

  9. What is the difference between List<?>, List<Object>, and List<? extends Object>? → List<?> accepts anything read-only, List<Object> needs exact Object, ? extends Object allows reading from any subtype.

  10. What is a generic method? → A method with its own type parameter.

  11. Can a generic class implement a non-generic interface? → Yes—no issues there.

  12. Can you create an array of generics? Why or why not? → No—runtime type erasure breaks array type safety.

  13. What is type inference? → The compiler guessing the generic type automatically.

  14. What are the limitations of generics in Java? → No primitives, no arrays, and erased types.

  15. Can you overload methods using generics? → Yes, but type erasure can cause conflicts.

  16. How do you create a generic class? → Add <T> after the class name and use T as a placeholder.

  17. What is the diamond operator (<>) in Java? → A shorthand letting the compiler infer generic types.

  18. What is the difference between compile-time and runtime type checking in generics? → Generics enforce type safety at compile-time; runtime sees erased types.

  19. What happens to generics during runtime? → They’re erased and operate as raw types.

  20. How do generics improve code reusability? → By letting one structure handle many data types safely.

Collections Framework (Deep Dive)

  1. How does an ArrayList work internally? → It uses a dynamic array that grows as needed.

  2. What happens when an ArrayList reaches its capacity? → It expands by creating a bigger array and copying elements.

  3. How does a LinkedList work internally? → It uses nodes linked together with next/previous pointers.

  4. What is the internal data structure of a HashSet? → A HashMap underneath, storing elements as keys.

  5. How does HashMap resolve hash collisions? → Using linked lists or balanced trees in buckets.

  6. What is rehashing in HashMap? → Recomputing bucket positions when resizing.

  7. How does the equals() and hashCode() contract affect HashMap behavior? → Proper hashing ensures correct key lookup and storage.

  8. What is the internal structure of a ConcurrentHashMap? → A segmented, lock-efficient hash table.

  9. What is the difference between ConcurrentHashMap and synchronizedMap()? → ConcurrentHashMap uses fine-grained locking; synchronizedMap locks the whole map.

  10. What is CopyOnWriteArrayList and how does it work? → A thread-safe list that copies the array on each write.

  11. What is the difference between Hashtable and ConcurrentHashMap? → Hashtable locks everything; ConcurrentHashMap locks only parts.

  12. What is the purpose of WeakHashMap? → To allow keys to be garbage collected when weakly referenced.

  13. What is the difference between TreeMap and LinkedHashMap? → TreeMap is sorted; LinkedHashMap keeps insertion order.

  14. How does LinkedHashMap maintain insertion order? → Through a doubly linked list of entries.

  15. How can you make a Collection thread-safe? → Use Collections.synchronizedXXX() or concurrent classes.

  16. What is the difference between synchronized collection and concurrent collection? → Synchronized is fully locked; concurrent allows safe parallel access.

  17. What is Enumeration and Iterator? → Enumeration is the old cursor; Iterator is modern and supports removal.

  18. What is a BlockingQueue? → A queue that waits when adding/removing until space/data appears.

  19. What is the difference between PriorityQueue and ArrayDeque? → PriorityQueue orders elements by priority; ArrayDeque is a fast double-ended queue.

  20. How do you sort a List of objects in Java? → Use Collections.sort() or list.sort() with a Comparator.

Functional Programming (Java 8 and Beyond)

  1. What are lambda expressions in Java? → Short functions written in a compact, arrow-style format.

  2. What is a functional interface? → An interface with exactly one abstract method.

  3. Give examples of built-in functional interfaces in Java. → Runnable, Predicate, Function, Supplier, Consumer.

  4. What is the difference between a lambda expression and an anonymous class? → Lambdas are shorter and focus on behavior, not type.

  5. What is the Predicate interface used for? → Testing a condition and returning true/false.

  6. What is the Function interface used for? → Converting one value into another.

  7. What is the Supplier interface used for? → Providing values without any input.

  8. What is the Consumer interface used for? → Accepting a value and performing an action.

  9. What is a method reference? → A shorthand way to refer to an existing method.

  10. What is the syntax for constructor references? → ClassName::new.

  11. What are streams in Java? → Pipelines for processing data in a functional style.

  12. What is the difference between intermediate and terminal operations in streams? → Intermediate steps transform data; terminal steps produce results.

  13. What are some examples of intermediate operations? → map, filter, sorted, flatMap, distinct.

  18. How can you filter and sort using streams? → Use filter() for conditions and sorted() for ordering.

  19. What are Optional objects in Java? → Containers that may or may not hold a value.

  20. What is the purpose of the Optional class, and how do you use it? → To avoid null checks—use methods like of(), empty(), get(), orElse().

⚙️ Batch 3 — Advanced Concurrency & Multithreading (Q201–Q300)

Threads & Life Cycle

  1. What are the different states of a thread in Java? → New, Runnable, Running, Blocked/Waiting, and Terminated — like a tiny worker with mood swings.

  2. How can you check if a thread is alive or not? → Use thread.isAlive() to see if it’s still buzzing around.

  3. What is the difference between start() and run() methods in threads? → start() creates a real new thread; run() is just a normal method pretending to be fancy.

  4. Can you call run() directly instead of start()? What happens? → Yes, but it runs on the same thread, so no actual “multithreading magic” happens.

  5. What is the life cycle of a thread? → It goes from born → runnable → running → waiting/blocking → done forever.

  6. What happens when the run() method throws an exception? → The thread quietly dies with that exception as its last words.

  7. How do you stop a thread gracefully? → Use a flag (like isRunning) and let the thread exit politely on its own.

  8. What is the volatile keyword used for? → It makes a variable always read the fresh, up-to-date value from memory.

  9. How is volatile different from synchronized? → volatile gives visibility, while synchronized gives both visibility and “one-at-a-time” access.

  10. What is the difference between Thread.sleep() and Object.wait()? → sleep() just pauses; wait() pauses and gives up the lock like a polite guest.

Synchronization

  1. What is synchronization in Java? → It’s Java’s way of making threads take turns instead of wrestling over shared data.

  2. Why is synchronization needed? → To stop threads from messing up shared variables like kids fighting over one toy.

  3. What are intrinsic locks or monitor locks? → Built-in locks every Java object secretly carries around like a personal door key.

  4. What is a synchronized method vs synchronized block? → A synchronized method locks the whole method; a block locks only the tiny part you choose.

  5. Can static methods be synchronized? → Yes, they lock on the class itself like a big global gate.

  6. What happens if one thread holds a lock and another tries to access it? → The second one just waits patiently like someone stuck outside a bathroom door.

  7. What is a reentrant lock? → A lock that lets the same thread enter again without getting locked out by itself.

  8. What are the disadvantages of synchronization? → Slower performance and the risk of deadlocks — like traffic jams for threads.

  9. What is the difference between synchronized and concurrent collections? → Synchronized ones block everything; concurrent ones let more action happen safely at once.

  10. What is thread interference? → When two threads scramble shared data by poking it at the same time.

Deadlock, Livelock & Starvation

  1. What is a deadlock? → It’s when two threads wait on each other forever like two people holding doors saying “you first.”

  2. What are the four conditions that cause deadlock? → Mutual exclusion, hold-and-wait, no preemption, and circular waiting — the four horsemen of thread misery.

  3. How do you detect a deadlock? → Look for threads stuck waiting on each other with no chance of escape.

  4. How can you prevent a deadlock? → Break at least one of the four conditions by ordering locks or avoiding long lock-holds.

  5. What is livelock? → Threads keep moving but never progress, like two people dancing sideways to avoid each other.

  6. What is thread starvation? → When one thread never gets CPU time because others hog the spotlight.

  7. What are some ways to avoid thread starvation? → Use fair locks, balanced priorities, and avoid greedy resource grabbing.

  8. Can deadlocks occur with only one thread? → Nope, you need at least two troublemakers.

  9. How do you debug deadlocks in Java? → Take thread dumps and look for threads stuck in BLOCKED with circular lock waits.

  10. What tools can be used to identify deadlocks? → JDK tools like jstack, VisualVM, Mission Control, and IntelliJ/IDE debuggers.

Thread Communication

  1. What is inter-thread communication? → It’s how threads politely talk and coordinate instead of bumping into each other.

  2. What are the three main methods of inter-thread communication? → wait(), notify(), and notifyAll() — the tiny messaging trio.

  3. What is the difference between notify() and notifyAll()? → notify() wakes one waiter; notifyAll() wakes the whole sleepy crowd.

  4. What happens if notify() is called with no waiting threads? → Nothing at all — it just vanishes into the void.

  5. Why must wait() and notify() be called inside synchronized blocks? → Because they need the object’s lock to avoid wild, unsafe wake-ups.

  6. What is spurious wakeup in Java? → When a thread wakes up even though nobody actually notified it — a random nudge.

  7. How can you handle spurious wakeups? → Always wait in a loop that re-checks the condition.

  8. Can wait() be interrupted? → Yes, and it throws InterruptedException to say so.

  9. What happens if wait() is called on an object without holding its lock? → It throws IllegalMonitorStateException like a strict bouncer.

  10. What is the purpose of the join() method in threads? → It makes one thread wait until another finishes its work.

Executor Framework

  1. What is the Executor Framework in Java? → A system that manages threads for you so you don’t juggle them manually.

  2. Why was the Executor Framework introduced? → To simplify thread management and make concurrency less chaotic.

  3. What is the difference between Executor and ExecutorService? → Executor just runs tasks; ExecutorService adds extras like shutdown and task tracking.

  4. What is the role of Callable and Future? → Callable returns a value; Future holds that value for later pickup.

  5. What is the difference between Runnable and Callable? → Runnable returns nothing; Callable returns something and can throw checked exceptions.

  6. What is the submit() method used for? → To send a task to the executor and get a Future back.

  7. What is a FutureTask? → A wrapper combining a task and its future result in one neat package.

  8. How do you cancel a running task? → Call future.cancel(true) and hope the task behaves.

  9. What are the different types of thread pools in Executors? → Fixed, cached, single-thread, and scheduled pools.

  10. How does a FixedThreadPool work? → It uses a set number of threads that reuse themselves endlessly.

  11. What is the difference between CachedThreadPool and FixedThreadPool? → Cached expands and shrinks freely; fixed stays the same size.

  12. What is a SingleThreadExecutor? → A pool with exactly one worker that handles tasks one by one.

  13. What is a ScheduledThreadPoolExecutor? → A pool that can delay or repeat tasks on a schedule.

  14. How do you schedule a task for repeated execution? → Use scheduleAtFixedRate() or scheduleWithFixedDelay().

  15. What is the difference between schedule() and scheduleAtFixedRate()? → schedule() runs once; scheduleAtFixedRate() repeats at steady intervals.

  16. What is the role of the RejectedExecutionHandler? → It decides what to do when the pool refuses a task.

  17. How do you shut down an executor service? → Call shutdown() or shutdownNow() politely or forcefully.

  18. What is the difference between shutdown() and shutdownNow()? → shutdown() lets tasks finish; shutdownNow() tries to stop everything instantly.

  19. What happens if you submit a task after shutdown? → You get a rejection because the pool has closed shop.

  20. How do you handle exceptions in threads using ExecutorService? → Catch them via Future.get() or wrap tasks with custom handlers.

Locks and Synchronizers

  1. What is the Lock interface in Java? → A manual lock you control yourself instead of relying on synchronized.
